1. What is an Operating System?

🎤 Interview answer

An Operating System is system software that acts as an interface between the user applications and the computer hardware. It manages hardware resources such as the CPU, memory, storage, and I/O devices, and provides services that applications need to run.

For example, when I run a Java application, I don't directly tell the CPU or memory how to execute it. The operating system manages those resources and provides the environment in which my application runs.

If interviewer asks: "What are the main responsibilities of an OS?"

You can say:

The major responsibilities of an OS are process management, memory management, file and storage management, I/O device management, CPU scheduling, and security and resource management.

🧠 Remember

OS = Interface + Resource Manager

2. What are the main functions of an Operating System?

🎤 Interview answer

The main functions of an operating system are process management, memory management, file management, I/O management, CPU scheduling, and security.

In process management, the OS creates and manages processes and threads. In memory management, it allocates and deallocates memory and manages virtual memory. It also manages files and storage, controls I/O devices, schedules CPU time among processes and threads, and provides security and access control.

If interviewer asks: "Can you explain each briefly?"

You can answer:

Function What OS does
Process Management Creates, schedules, and terminates processes
Memory Management Allocates memory and manages virtual memory
CPU Scheduling Decides which runnable process/thread gets CPU time
File Management Creates, reads, writes, and organizes files
I/O Management Manages devices such as keyboard, disk, network
Security Controls access to resources
Resource Management Allocates hardware resources among programs

🧠 Interview trick

Don't just list them. Give one line explaining each. That makes your answer sound like you understand the concept rather than memorized a list.

3. What is the difference between a Program and a Process?

This is very important. ⭐⭐⭐⭐⭐

🎤 Interview answer

A program is a passive set of instructions stored on a storage device, whereas a process is a program that is currently being executed.

A program itself doesn't have an execution state, CPU state, or resources allocated to it. When we run a program, the operating system loads the required parts into memory, allocates resources, and creates a process to execute it.

For example, a Java application stored as a .class or .jar file is a program. When I run that application, the OS creates a process for its execution.

Simple example

Think about a recipe:

Recipe stored in a book
        ↓
      Program

Someone actually cooking it
        ↓
      Process

⭐ If interviewer asks: "Can multiple processes come from one program?"

Say:

Yes. The same program can be executed multiple times, and each execution can result in a separate process with its own execution state and resources.

4. What is a Process?

🎤 Interview answer

A process is a program in execution. It is an active entity that contains the program's instructions along with the execution state and resources required to execute them.

A process has information such as its process ID, program counter, CPU registers, memory information, and scheduling information. The operating system maintains this information using a data structure called the Process Control Block, or PCB.

That's a strong fresher-level answer.

If interviewer asks:

"Is a process just a program loaded into memory?"

Don't say simply yes.

Say:

Not exactly. A process includes not only the program's instructions but also its current execution state, memory, CPU state, and other resources required for execution.

That's an important distinction.

5. What are the different states of a Process?

This is another must-know OS question. ⭐⭐⭐⭐⭐

🎤 Interview answer

A process typically goes through several states during its lifetime: New, Ready, Running, Waiting or Blocked, and Terminated.

In the New state, the process is being created. In the Ready state, it is ready to execute but is waiting for CPU time. In the Running state, it is currently executing on the CPU. If it needs to wait for an I/O operation or some event, it moves to the Waiting or Blocked state. Once the event is completed, it moves back to Ready. Finally, when the process finishes execution, it enters the Terminated state.

🧠 Understand the flow

                 │     New     │
                 └──────┬──────┘
                        ↓
                 ┌─────────────┐
          ┌──────│    Ready    │◄──────────┐
          │      └──────┬──────┘           │
          │             ↓                  │
          │      ┌─────────────┐           │
          │      │   Running   │           │
          │      └───┬─────┬───┘           │
          │          │     │               │
          │          │     ↓               │
          │          │  Terminated         │
          │          │                     │
          │          ↓                     │
          │      ┌─────────────┐           │
          └──────│   Waiting   │───────────┘
                 │  / Blocked  │
                 └─────────────┘

The important transitions

New → Ready

Process has been created and is ready to run.

Ready → Running

CPU scheduler selects it.

Running → Waiting

Process needs I/O or has to wait for an event.

Waiting → Ready

The required event/I/O completes.

Running → Ready

The OS preempts it, for example because its time slice expires.

Running → Terminated

Process finishes execution.

6. What is a Process Control Block (PCB)?

🎤 Interview answer

A Process Control Block, or PCB, is a data structure maintained by the operating system to store important information about a process.

It contains information such as the process ID, process state, program counter, CPU registers, scheduling information, and memory management information.

The OS uses the PCB to keep track of a process and to save and restore its execution state, especially during context switching.

🧠 Think of it like this

Process
   ↓
OS needs to remember everything about it
   ↓
PCB

For example:

PCB
├── PID
├── Process State
├── Program Counter
├── CPU Registers
├── Scheduling Information
├── Memory Information
└── I/O Information

🔥 Follow-up: Why is PCB important during context switching?

When the CPU switches from one process to another, the OS needs to save the current process's execution state and later restore it. The PCB contains much of the information required to do this.

7. What is a Process ID (PID)?

🎤 Interview answer

A Process ID, or PID, is a unique identifier assigned by the operating system to identify a process.

The OS uses the PID to keep track of processes and perform operations such as scheduling, terminating, or managing a particular process.

For example, conceptually:

Chrome     → PID 1200
Java       → PID 2450
VS Code    → PID 3100

The actual PID values depend on the operating system and current processes.

🔥 Follow-up: Why do we need a PID?

Because multiple processes can exist simultaneously, the OS needs a way to uniquely identify and manage each process.

8. What is Context Switching? ⭐⭐⭐⭐⭐

This is very important.

🎤 Interview answer

Context switching is the process of switching the CPU from one process or thread to another.

When the OS decides to stop the currently running process or thread, it saves its execution state, such as the program counter and CPU registers. It then loads the saved state of another process or thread, allowing that process or thread to continue execution from where it previously stopped.

Context switching enables multitasking, but it also introduces some overhead because the CPU spends time saving and restoring state instead of executing application code.

🧠 Example

Suppose:

CPU
 ↓
Java

Java is executing.

Then the scheduler decides:

"Give CPU to Chrome."

The OS does roughly:

Java running
     ↓
Save Java's context
     ↓
Load Chrome's context
     ↓
Chrome runs

Later:

Chrome
   ↓
Save Chrome's context
   ↓
Load Java's context
   ↓
Java continues

🔥 Important follow-up

Does context switching happen only between processes?

No.

Context switching can happen between processes as well as between threads.

9. What is a Thread?

🎤 Interview answer

A thread is the smallest unit of execution within a process. A process can contain one or multiple threads, and threads within the same process share resources such as the process's address space, while each thread maintains its own execution state, such as its stack and CPU registers.

Threads allow a process to perform multiple tasks concurrently.

🧠 Simple picture

             Process
                │
       ┌────────┼────────┐
       ↓        ↓        ↓
   Thread 1  Thread 2  Thread 3

For example, a server process might have different threads handling different pieces of work.

🔥 Follow-up: Why do we need threads?

Threads allow multiple tasks within the same process to make progress concurrently while sharing the process's resources. This can improve responsiveness and resource utilization.

10. What is the difference between a Process and a Thread? ⭐⭐⭐⭐⭐

This is one of the most commonly asked OS questions.

🎤 Interview answer

A process is an independent program in execution, whereas a thread is an execution unit within a process.

Processes generally have separate address spaces, while threads belonging to the same process share the process's address space and many resources. Because of this, creating and switching between threads is generally less expensive than doing the same with separate processes, although the exact cost depends on the operating system.

However, sharing memory between threads also means that synchronization is required when multiple threads access shared data.

🔥 Comparison

Process Thread
Independent execution environment Execution unit within a process
Separate address space Threads share process address space
More resource overhead Generally lower overhead
Communication usually requires IPC mechanisms Communication can use shared memory
Failure is generally more isolated A serious thread failure can affect the process
Context switching is generally more expensive Generally cheaper

11. Why are threads called lightweight processes?

🎤 Interview answer

Threads are called lightweight processes because they require fewer resources to create and manage compared to processes. Threads within the same process share resources such as the address space, code, and open files, whereas separate processes generally have separate address spaces and more independent resources.

Therefore, thread creation and context switching are generally less expensive than process creation and context switching.

🧠 Simple way to remember

Process
├── Own memory space
├── Own resources
└── Thread(s)

Thread
├── Shares process memory
├── Own stack
└── Own CPU state

🔥 Follow-up

Does lightweight mean threads don't have their own memory?

No. Threads share the process's address space, but each thread still has its own stack, registers, program counter, and execution state.

12. What resources are shared between threads of the same process?

🎤 Interview answer

Threads within the same process share the process's address space and resources such as code, global variables, heap memory, and open files. However, each thread maintains its own execution-related information such as its stack, registers, and program counter.

Think:

             PROCESS
┌──────────────────────────────┐
│                              │
│   Code        ← Shared       │
│   Heap        ← Shared       │
│   Global data ← Shared       │
│   Open files  ← Shared       │
│                              │
│   ┌──────┐ ┌──────┐ ┌──────┐│
│   │ T1   │ │ T2   │ │ T3   ││
│   │Stack │ │Stack │ │Stack ││
│   └──────┘ └──────┘ └──────┘│
│      Private   Private       │
└──────────────────────────────┘

⭐ Important distinction

Shared:

  • Code
  • Heap
  • Global/static data
  • Many process resources, such as open files

Private to each thread:

  • Stack
  • Registers
  • Program counter
  • Thread-local storage

13. What resources are private to each thread?

🎤 Interview answer

Each thread has its own program counter, CPU registers, and stack. These are private because each thread can be executing a different function or instruction at the same time and therefore needs its own execution state.

For example:

Thread 1 → executing function A
Thread 2 → executing function B

They can't use the same stack because their function calls and local variables are different.

So:

Thread 1
 ├── Program Counter
 ├── Registers
 └── Stack

Thread 2
 ├── Program Counter
 ├── Registers
 └── Stack

14. What is Multithreading?

🎤 Interview answer

Multithreading is the ability of a process to execute multiple threads concurrently. Each thread can perform a different task while sharing the resources of the same process.

For example, a web server can use multiple threads to handle multiple client requests, allowing different requests to make progress without requiring a completely separate process for each request.

Example

Imagine your backend:

             Backend Process
                   │
       ┌───────────┼───────────┐
       ↓           ↓           ↓
    Thread 1    Thread 2    Thread 3
     Login       Profile     Booking

The threads share the process's resources.

🔥 Follow-up

What is the advantage of multithreading?

It can improve responsiveness and resource utilization and allow multiple tasks to make progress concurrently. It can also take advantage of multiple CPU cores for parallel execution.

15. What are the advantages and disadvantages of Multithreading?

🎤 Interview answer

The main advantages of multithreading are improved responsiveness, better CPU utilization, the ability to perform multiple tasks concurrently, and efficient sharing of resources within a process.

However, multithreading also introduces challenges such as race conditions, synchronization overhead, deadlocks, and the difficulty of debugging concurrent programs.

✅Advantages

1. Better responsiveness

One thread can continue while another waits for I/O.

2. Better CPU utilization

Multiple threads can keep CPU cores busy.

3. Resource sharing

Threads share the process's memory and resources.

4. Concurrency

Multiple tasks can make progress at the same time.

❌Disadvantages ⚠️

1. Race conditions

Multiple threads access shared data incorrectly.

2. Synchronization overhead

Locks and other synchronization mechanisms add overhead.

3. Deadlocks

Threads can become stuck waiting for each other.

4. Debugging difficulty

Concurrency bugs can be difficult to reproduce.

16. What happens when a process creates a child process?

🎤 Interview answer

When a process creates another process, the original process is called the parent process and the newly created process is called the child process. The operating system assigns the child process its own process ID and creates the necessary process management information for it.

The child may inherit or share certain resources from the parent depending on the operating system and how the process is created, but the child is a separate process with its own execution state.

Simple picture

        Parent Process
              │
        creates child
              ↓
        Child Process

For example, in Unix-like systems, a process can create another process using fork().

Conceptually:

Before fork():

      Parent

After fork():

      Parent
        │
        └────── Child

Both can then execute independently.

🔥 Follow-up

Does the child have the same PID as the parent?

No. The child receives a different PID. The parent and child are separate processes.

17. What is a Parent Process and Child Process?

🎤 Interview answer

A parent process is a process that creates another process, while the newly created process is called the child process. The operating system maintains a relationship between them so that the parent can manage or wait for its child.

The child has its own process ID and execution state, although it may inherit certain attributes or resources from the parent depending on the operating system.

Example

             OS
              │
        Parent Process
              │
       ┌──────┴──────┐
       ↓             ↓
    Child A       Child B

A parent can have multiple children.

18. What is a Zombie Process? ☠️

This is a very common interview question.

🎤 Interview answer

A zombie process is a process that has finished execution, but its entry in the process table still exists because its parent has not yet collected its termination status.

The process itself is no longer executing, but the OS keeps a small amount of information about it, such as its PID and exit status, so that the parent can retrieve that information.

Understand the flow

Parent
  │
  └── creates Child
          │
          ↓
       Running
          │
          ↓
       Finishes
          │
          ↓
       Zombie
          │
          ↓
 Parent collects exit status
          │
          ↓
       Removed

The parent typically does this through a mechanism such as wait()/waitpid() on Unix-like systems.

🧠 Important

A zombie is not running.

It is essentially:

Finished process + remaining process-table entry

🔥 Follow-up

Why does a zombie exist?

Because the OS needs to retain the child's termination status until the parent retrieves it.

19. What is an Orphan Process?

🎤 Interview answer

An orphan process is a process whose parent has terminated while the child is still running. The operating system then reassigns or adopts the orphan under another system process so that it can continue to be managed properly.

Example

Parent
  │
  └── Child
        │
        │ Parent terminates
        ↓
      Orphan
        │
        ↓
 Adopted by another system process

20. What is the difference between Concurrency and Parallelism? ⭐⭐⭐⭐⭐

This is very important.

🎤 Interview answer

Concurrency means multiple tasks are making progress during overlapping periods, while parallelism means multiple tasks are actually executing at the same time, typically on different CPU cores.

Concurrency can happen even on a single CPU core through techniques such as context switching. Parallelism generally requires multiple execution units, such as multiple CPU cores, to execute tasks simultaneously.

🔥 Example: Single Core

Suppose:

Task A
Task B
Task C

One CPU core:

CPU Core

A → B → A → C → B → A → ...

Only one task is executing at any instant.

But all three tasks are making progress over time.

That's:

Concurrency

🔥 Example: Multiple Cores

Suppose you have 3 CPU cores:

Core 1 → Task A
Core 2 → Task B
Core 3 → Task C

A, B and C can actually execute simultaneously.

That's:

Parallelism

21. What is CPU Scheduling?

🎤 Interview answer

CPU scheduling is the process of selecting a process or thread from the ready queue and allocating the CPU to it. Since multiple processes may be ready to execute at the same time, the operating system uses scheduling algorithms to decide which one should run next.

Example

Suppose:

Ready Queue:

P1
P2
P3
P4

But you have only one CPU core.

The OS needs to decide:

Who gets the CPU first?
        ↓
      P2

Then after P2:

P2 → P4 → P1 → P3

The scheduler makes these decisions.

🎯 Why do we need CPU scheduling?

Because we want to:

  • Keep the CPU busy
  • Improve response time
  • Reduce waiting time
  • Improve throughput
  • Provide fairness

22. What is a Scheduler?

🎤 Interview answer

A scheduler is an operating-system component that decides which process or thread should be selected for execution from the available processes. The short-term scheduler, also called the CPU scheduler, selects a ready process or thread and gives it the CPU.

Think:

           Ready Queue
        ┌───┬───┬───┬───┐
        │ P1│ P2│ P3│ P4│
        └───┴───┴───┴───┘
                 │
                 ↓
             Scheduler
                 │
                 ↓
                CPU

🔥 Scheduler vs Scheduling

Don't confuse these:

Scheduler → the component making the decision.

Scheduling → the process of deciding who gets the CPU.

23. What are the different types of schedulers?

There are traditionally three types you should know.

1. Long-Term Scheduler

Also called the job scheduler.

It decides:

Which jobs/processes should be admitted into the system for execution?

Conceptually:

Jobs on disk
     ↓
Long-term scheduler
     ↓
Processes in memory

It controls the degree of multiprogramming — roughly, how many processes are admitted to the system.

2. Short-Term Scheduler ⭐⭐⭐⭐⭐

Also called the CPU scheduler.

It decides:

Which ready process/thread should get the CPU next?

Ready Queue
    ↓
Short-term scheduler
    ↓
CPU

This scheduler runs very frequently, so it needs to be fast.

3. Medium-Term Scheduler

It can temporarily remove processes from memory and later bring them back.

This is associated with swapping.

Conceptually:

Memory
  ↓
Medium-term scheduler
  ↓
Temporarily remove process
  ↓
Disk

Later:

Disk
 ↓
Memory

🎤 Interview answer

"Traditionally, operating systems describe three types of schedulers: the long-term scheduler, which controls which jobs are admitted; the short-term scheduler, which selects the next ready process or thread for the CPU; and the medium-term scheduler, which can temporarily suspend or swap processes to manage memory and the degree of multiprogramming."

24. What is Preemptive vs Non-Preemptive Scheduling? ⭐⭐⭐⭐⭐

This is very important.

The question is basically:

Can the OS take the CPU away from a running process?

🟢 Non-Preemptive Scheduling

Once a process gets the CPU:

It keeps the CPU until it finishes or voluntarily blocks/waits.

Example:

P1 gets CPU
      ↓
P1 keeps CPU
      ↓
P1 finishes
      ↓
P2 gets CPU

The OS doesn't forcibly interrupt P1 just because another process has become ready.

Examples:

  • FCFS
  • Traditional non-preemptive SJF

🔴 Preemptive Scheduling

The OS can interrupt a running process and give the CPU to another process.

Example:

P1 running
   ↓
Timer interrupt
   ↓
OS scheduler
   ↓
P1 paused
   ↓
P2 gets CPU

This is how systems can provide responsive multitasking.

Examples:

  • Round Robin
  • SRTF
  • Preemptive Priority Scheduling

🎤 Interview answer

"In preemptive scheduling, the operating system can interrupt a running process and allocate the CPU to another process. In non-preemptive scheduling, once a process gets the CPU, it generally keeps it until it finishes or blocks voluntarily. Preemptive scheduling generally provides better responsiveness, but it introduces additional context-switching overhead."

25. What is FCFS Scheduling?

FCFS = First Come, First Served

It's one of the simplest CPU scheduling algorithms.

The rule is:

The process that arrives first gets the CPU first.

Just like standing in a queue.

Ready Queue:

P1 → P2 → P3 → P4

CPU:

P1 → P2 → P3 → P4

Example

Suppose:

Process Arrival Time Burst Time
P1 0 5
P2 1 3
P3 2 2

FCFS gives:

0        5        8       10
|--------|--------|--------|
   P1       P2       P3

P1 arrives first → runs first.

Then P2.

Then P3.

🔥 The major problem with FCFS

Imagine:

P1 = 20 seconds
P2 = 2 seconds
P3 = 2 seconds

And they arrive in that order.

FCFS:

P1 ────────────────────
                       P2 ──
                            P3 ──

P2 and P3 are tiny jobs, but they have to wait for the huge P1.

This is called the:

Convoy Effect

🎤 Interview answer

"FCFS is a non-preemptive scheduling algorithm where processes are executed in their order of arrival. It is simple and fair in terms of arrival order, but it can cause high waiting time and the convoy effect, where short processes are forced to wait behind a long-running process."

26. What is SJF Scheduling?

SJF = Shortest Job First

The idea is simple:

Among the available processes, the process with the shortest CPU burst time is selected first.

Example

Suppose:

Process Burst Time
P1 8 ms
P2 3 ms
P3 5 ms
P4 2 ms

SJF chooses:

P4 → P2 → P3 → P1
 2     3     5     8

🎤 Interview answer

SJF, or Shortest Job First, is a CPU scheduling algorithm that selects the process with the shortest expected CPU burst time among the available processes. It can minimize average waiting time when burst times are known or estimated, but accurately knowing the future CPU burst time can be difficult.

⭐Important point ⚠️

Traditional SJF is non-preemptive.

Once a process starts:

P1 running
   ↓
P1 continues
   ↓
P1 finishes
   ↓
Next process

27. What is SRTF Scheduling?

SRTF = Shortest Remaining Time First

Think of it as:

Preemptive version of SJF.

Instead of asking:

"Which process has the shortest total burst time?"

we ask:

"Which available process has the shortest remaining execution time?"

Example

Suppose:

P1 arrives at time 0
Burst = 8

So:

Time 0 → P1 starts

At time 2:

P2 arrives
Burst = 3

P1 has:

8 - 2 = 6 ms remaining

P2 needs:

3 ms

So SRTF says:

"P2 needs less time. I'll pause P1."

P1 running
   ↓
P2 arrives
   ↓
P1 paused
   ↓
P2 runs
   ↓
P2 finishes
   ↓
P1 resumes

🎤 Interview answer

SRTF, or Shortest Remaining Time First, is the preemptive version of SJF. The scheduler always selects the available process with the shortest remaining CPU burst time. If a new process arrives with a shorter remaining time than the currently running process, the current process can be preempted.

🧠 Remember

SJF  → Shortest Job → Non-preemptive
SRTF → Shortest Remaining Time → Preemptive

28. What is Round Robin Scheduling? ⭐⭐⭐⭐⭐

This is very commonly asked.

Round Robin is designed particularly for time-sharing systems.

The key concept is:

Each process gets a fixed amount of CPU time called a time quantum/time slice.

Imagine:

Ready Queue:

P1 → P2 → P3

Suppose:

Time quantum = 2 ms

Then:

P1 → 2 ms
P2 → 2 ms
P3 → 2 ms
P1 → 2 ms
P2 → 2 ms
P3 → 2 ms
...

It's like everyone gets a turn.

🎤 Interview answer

Round Robin is a preemptive CPU scheduling algorithm where each ready process is given a fixed time quantum. When its time quantum expires, the process is preempted and moved to the back of the ready queue if it still has work to do. This provides fairness and good responsiveness for interactive systems.

🔥 What happens if the time quantum is too small?

Suppose:

Time quantum = 1 ms

Then:

P1 → P2 → P3 → P1 → P2 → P3 → ...

There will be lots of context switches.

That creates context-switching overhead.

What if the time quantum is too large?

Round Robin starts behaving more like FCFS because processes may run for long periods before another process gets a turn.

So there is a trade-off.

29. What is Priority Scheduling?

Here the scheduler gives preference based on priority.

For example:

P1 → Priority 3
P2 → Priority 1
P3 → Priority 2

Assuming smaller number means higher priority:

P2 → P3 → P1

🎤 Interview answer

Priority scheduling is a scheduling algorithm where each process is assigned a priority, and the scheduler selects a process based on that priority. It can be implemented as either preemptive or non-preemptive scheduling. A problem with priority scheduling is that low-priority processes may wait indefinitely if higher-priority processes keep arriving.

That problem is called:

Starvation

30. What is Starvation and how can it be prevented?

🎤 Interview answer

Starvation occurs when a process waits for a very long time, potentially indefinitely, because other processes keep getting preference for the required resource, such as CPU time.

One common way to prevent starvation is aging, where the priority of a waiting process is gradually increased over time so that it eventually gets a chance to execute.

Example

Suppose:

P1 → Low priority

But new high-priority processes keep arriving:

High → High → High → High → High → ...

P1 keeps waiting:

P1
 ↓
waiting...
 ↓
waiting...
 ↓
waiting...

😢

That's starvation.

Aging

We gradually increase P1's priority:

P1 priority = 10
       ↓
waits
       ↓
priority = 8
       ↓
waits
       ↓
priority = 5
       ↓
waits
       ↓
priority = 1
       ↓
P1 gets CPU

The exact priority direction depends on the scheduling convention, but the idea is:

The longer a process waits, the more its priority is boosted.

Algorithm Main idea Preemptive?

🎯 One thing to be very clear about

Don't confuse starvation with deadlock.

Starvation

A process can potentially run, but keeps getting denied because other processes are preferred.

Deadlock

Processes are stuck waiting for each other/resources, so none of them can proceed.

31. What is a Race Condition? ⭐⭐⭐⭐⭐

A race condition occurs when multiple threads/processes access shared data concurrently, and the final result depends on the order/timing of their execution.

🎤 Interview answer

A race condition occurs when multiple threads access and modify shared data concurrently, and the final result depends on the timing or order in which the threads execute. This can lead to incorrect or unpredictable results.

It can be prevented by properly synchronizing access to the shared resource.

Let's understand it with Java

Suppose:

int count = 0;

Two threads execute:

count++;

You might think:

0 → 1 → 2

So the answer should be 2.

But count++ is not one indivisible operation.

Conceptually:

Read count
   ↓
Add 1
   ↓
Write count

Now imagine:

Initial count = 0

Thread 1: Read 0
Thread 2: Read 0

Thread 1: Add 1 → 1
Thread 2: Add 1 → 1

Thread 1: Write 1
Thread 2: Write 1

Final result:

count = 1 ❌

Even though two increments happened.

That's a race condition.

🧠 Remember

Race condition = result depends on who gets there first.

32. What is a Critical Section? ⭐⭐⭐⭐⭐

A critical section is the part of a program where shared data/resource is accessed or modified and therefore needs controlled access.

🎤 Interview answer

A critical section is a section of code that accesses shared resources and must be executed in a controlled manner so that multiple threads do not simultaneously perform conflicting operations on the shared resource.

Example:

balance = balance - 500;

If multiple threads can modify balance, this operation may need to be protected.

Conceptually:

Thread 1
   ↓
┌──────────────────┐
│ Critical Section │
│                  │
│ modify balance   │
│                  │
└──────────────────┘

The goal is generally:

Only one thread at a time should execute the conflicting critical section.

🔥 Critical Section vs Race Condition

Don't confuse them.

Critical section = the code region accessing shared data.

Race condition = the problem that can happen when concurrent access isn't properly controlled.

Shared resource
      ↓
Critical Section
      ↓
Improper concurrent access
      ↓
Race Condition ❌

33. What is Process/Thread Synchronization?

🎤 Interview answer

Synchronization is the coordination of multiple processes or threads when they access shared resources, so that their operations occur safely and consistently without causing race conditions or data corruption.

Operating systems and programming languages provide mechanisms such as mutexes, semaphores, monitors, and locks to achieve synchronization.

Why do we need it?

Imagine:

Bank balance = ₹1000

Thread A → withdraw ₹700
Thread B → withdraw ₹500

Both threads access the same balance.

Without synchronization:

Thread A ──┐
           ├──→ Shared Balance
Thread B ──┘

They can interfere with each other.

With synchronization:

Thread A
   ↓
[LOCK]
   ↓
Modify balance
   ↓
[UNLOCK]
   ↓
Thread B

34. What is a Mutex? 🔒 ⭐⭐⭐⭐⭐

Mutex = Mutual Exclusion

The easiest way to understand a mutex:

A mutex is a lock that allows only one thread at a time to enter a protected critical section.

🎤 Interview answer

A mutex, or mutual exclusion lock, is a synchronization mechanism used to protect shared resources. At most one thread can hold the mutex at a time. A thread must acquire the mutex before entering the protected critical section and release it after finishing.

Example:

             Mutex
               🔒
                │
        ┌───────┴───────┐
        ↓               ↓
    Thread A          Thread B
        │               │
     acquire         waiting
        │
        ↓
 Critical Section
        │
      release
        │
        ↓
                    Thread B
                    acquire

So:

Thread A has the lock → Thread B waits.

35. What is a Semaphore? 🚦 ⭐⭐⭐⭐⭐

A semaphore is another synchronization mechanism, but its model is different from a mutex.

Think of a semaphore as a counter representing available permits/resources.

🎤 Interview answer

A semaphore is a synchronization mechanism that maintains a count of available permits. A thread acquires a permit before accessing a limited resource and releases it when it is finished. If no permit is available, the thread waits. A counting semaphore can therefore allow a limited number of threads to access a resource concurrently.

Example

Suppose a server has 3 database connections available.

Semaphore = 3

Then:

Thread 1 → gets connection
Thread 2 → gets connection
Thread 3 → gets connection

Now:

Semaphore = 0

Thread 4 has to wait.

When Thread 1 releases its connection:

Semaphore = 1

Thread 4 can acquire it.

🔥 Mutex vs Semaphore

This is a very common interview follow-up.

Mutex Semaphore
Primarily provides mutual exclusion Controls access using permits/count
Usually one thread owns the lock at a time Can allow multiple concurrent holders
Commonly used to protect a critical section Commonly used to control a limited resource
Ownership is typically associated with the locking thread No equivalent ownership requirement in the basic semaphore model
Usually binary: locked/unlocked Can be binary or counting

Example

Mutex:

One bathroom 🚪

Only ONE person at a time.

Semaphore:

Parking lot 🅿️

5 spaces available.

5 cars → allowed
6th car → waits

That's a very useful mental model.
